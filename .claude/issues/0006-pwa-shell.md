## Goal

Make the Nuxt app (`apps/web`) installable as a Progressive Web App so a self-hosted `dbboard-web` instance can be added to a phone's home screen for ambient, read-mostly access (think GitHub mobile app: glance at production signup counts during a meeting, verify a specific order, kill a long-running query from a phone).

Strategic context lives in [`handoff/2026-05-26-pwa-pivot-incoming.md`](../handoff/2026-05-26-pwa-pivot-incoming.md):

- No native Android / iOS apps. No `dbboard-mobile` repo.
- PWA-ify `dbboard-web` instead. One codebase covers laptop browsers and mobile install.
- Forward-compatible with desktop ADR-0011 (HTTP contract = public API) and ADR-0012 (Capability pattern). No contract churn.

This phase touches the application shell only — manifest, service worker, responsive layout, install prompt. It does **not** depend on the HTTP contract, so it proceeds in parallel with the wait on desktop's `/capabilities` publication (which gates `0003`/`0004`/`0005`).

## Scope

1. `apps/web/public/manifest.json` — `name`, `short_name`, `icons` (192×192 and 512×512, both with a `purpose: "maskable"` variant), `start_url`, `display: standalone`, `theme_color`, `background_color`.
2. Nuxt PWA module (`@vite-pwa/nuxt`) — auto-generated service worker, Workbox precache, an explicit offline fallback page (no white screen on cold offline start).
3. Install prompt UI — capture `beforeinstallprompt`, surface as opt-in (e.g. a small "Install" affordance in settings or a one-time inline hint). Never auto-push the dialog.
4. iOS Safari support — `apple-touch-icon`, `apple-mobile-web-app-capable`, `apple-mobile-web-app-status-bar-style`. iOS 16.4+ exposes Web Push, but Web Push itself is out of scope (see below).
5. Mobile-first responsive review of the current Nuxt smoke page so the responsive baseline is in place before Phase 4 builds real UI on top of it. At 375 × 667: schema sidebar collapses, SQL editor stacks vertically, results table scrolls horizontally, touch targets are ≥ 44 × 44 px.
6. Icon asset pipeline — generate the required icon sizes from a single source SVG via `@vite-pwa/assets-generator` (or equivalent), checked into `apps/web/public/`.

## Out of scope

- **Web Push notifications.** Optional follow-up, not part of this issue. When picked up later: VAPID key generated locally + the `web-push` Node library for self-hosted delivery. No vendor lock-in.
- **Authentication.** PWA installability does not require auth.
- **Offline write queue.** The read-mostly assumption makes this non-essential. The offline fallback is read-only.
- **Native apps / `dbboard-mobile` repo.** Revisit only after PWA demand is observable in practice.
