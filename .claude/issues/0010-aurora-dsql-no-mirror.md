## Disposition

Closed as **no-op**. The technical claim — verified on the web side — is that **Aurora DSQL URLs are pg-wire and route through the existing `PostgresAdapter`** shipped in ticket [`0004`](./0004-phase-2-postgres-adapter.md) (PR #9, `dbboard-web@0dc1a1b`). No new adapter, no new endpoint, no new DTO, no new error category, no new HTTP status code. `docs/api-contract.md` is untouched.

The only Aurora DSQL-specific concern is the auth model: the password segment of the connection URL must carry a short-lived **IAM authentication token** (~15 min TTL) generated by the AWS CLI (`aws dsql generate-db-connect-auth-token`) or the AWS SDK (`@aws-sdk/dsql-signer` on the JS/TS side). That UX expectation is documented in [`../../docs/deployment.md`](../../docs/deployment.md) § "Connecting to Aurora DSQL (IAM-token URLs)".

This issue exists for accounting only — it closes the desktop-wait flag in `project-status.md` and gives a stable anchor for the no-op disposition that the brief's acceptance checklist requires.
